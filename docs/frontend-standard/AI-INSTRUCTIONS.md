# 给开发 AI 的接入指令

适用规范：前端与 VI 规范 1.0，2026-11-23（Asia/Shanghai，UTC+8）。

## 获取方式 A：固定版本 URL

先完整读取主规范：
https://raw.githubusercontent.com/CosmoGao/frontend-standard/v1.0.0/FRONTEND-SPEC.md

如需完整包，再读取同版本 `AI-INSTRUCTIONS.md`、`CHECKLIST.md`、`tokens.json` 与 `tokens.css`。不要假定某个工具会自动追随 README 或链接；应明确读取每个需要的文件。

可复制给 agent：

> 请先完整读取 https://raw.githubusercontent.com/CosmoGao/frontend-standard/v1.0.0/FRONTEND-SPEC.md ，再按其规范进行本次授权的前端开发；保留现有产品名称与logo，复用组件、使用语义令牌并完成浅深/宽窄屏/键盘验收。遵循更高优先级项目指令，冲突需报告，不擅自覆盖。如果无法读取 raw 链接，请尝试 https://github.com/CosmoGao/frontend-standard/blob/v1.0.0/FRONTEND-SPEC.md ，或明确请求提供下载后的本地文件；不得声称已读取不可访问的内容。

URL 可达性取决于 agent 工具权限和网络，不保证自动获取。固定版本整包：
https://github.com/CosmoGao/frontend-standard/releases/download/v1.0.0/frontend-standard-v1.zip

## 获取方式 B：本地 vendor 或单文件

下载同版本 Release ZIP，将包内规范内容复制至项目 `docs/frontend-standard/`，之后按下方本地接入要求执行。也可只上传主规范；不得要求其他 agent 访问作者机器上的任何路径。

## 1. 最短任务提示（单文件）

把 `FRONTEND-SPEC.md` 上传给 AI，并附上：

> 请先完整读取所附《前端与 VI 规范》1.0，再进行我本次授权的前端开发。把它作为视觉、组件状态、布局、响应式与验收基线；先检查当前项目指令和现有组件，复用组件、使用语义令牌，不擅自改产品名称、logo 或 VI。先说明将使用的页面模板、组件映射、项目可配置品牌项及冲突。只拿到主规范时也要按其令牌表实现浅深主题与完整状态；不能自行另造色值或忽略无障碍/滚动/触控规则。遵循更高优先级项目指令，冲突时列出，不自行覆盖。完成后按主规范的验收项报告具体测试证据和未完成项。

## 2. 完整包放入项目

建议复制本目录至 `docs/frontend-standard/`。仅加入文档和 token 并不自动修改现有页面；由项目实际开发任务决定实施范围。

把以下片段**合并追加**到已有 `AGENTS.md`、`CLAUDE.md` 或所用开发工具的项目规则文件中，不覆盖原文件，不删除既有指令。路径按实际目录调整。项目规则文件格式不支持 Markdown 时按其合法格式转写同样含义，不盲目粘贴。

```markdown
## 前端与 VI 基线

涉及 UI/前端页面、主题、组件或品牌呈现的任务时：
1. 完整读取 docs/frontend-standard/FRONTEND-SPEC.md（v1.0）。
2. 读取 docs/frontend-standard/AI-INSTRUCTIONS.md 和 CHECKLIST.md。
3. 以 tokens.json 为机器值来源，tokens.css 为可直接导入的变量；
   主规范是解释与验收来源。不一致时报告并修复，不随意择一。
4. 先复用本项目组件与业务结构，使用语义 token、统一状态；
   禁止未经批准更改产品名、logo、主色或自行新增品牌风格。
5. 保持固定应用壳与独立主内容滚动、位置表达去重、
   桌面正文14/22、默认控件36、compact32、触控主要操作至少44。
6. 浅深主题都实现 hover/active/focus/disabled/loading/selected/invalid，
   必要控件轮廓用 control-border，不拿装饰 border 代替。
7. 项目品牌配置与现有项目指令优先级按仓库约定执行；
   本规范不覆盖更高优先级的安全、业务及开发规则。冲突须明确报告。
8. 完成后逐条执行 CHECKLIST.md；报告路由、视口、测试结果与截图，
   未执行的项写“未验证”，不得把 token 校验当整站认证。
```

若项目已有不同版本规范，MUST 先列差异，按当前授权范围迁移，不同时保留两个不明真源。跨多个 AI 工具使用时让各入口引用同一主规范路径，而不是复制多份逐渐分叉的全文。

## 3. 开工前的输出格式

```text
本次范围：实际授权的路由/组件
规则来源与优先级：项目规则 → 本规范/项目批准的覆盖
组件复用：现有组件 → 本次用途 → 必要补齐状态
页面模板：列表/详情/表单/总览（按实际选用）
品牌：保留现有名称与资产；缺失参数标为可配置
差异与冲突：具体条款/解决方式/需要批准的覆盖
验收计划：浅深、桌面/窄屏、键盘、内容状态、截图
```

不要求创建新的技术栈。React + TypeScript + shadcn/ui + Tailwind 是候选，不是强制；Vue、Svelte 或已有组件库可用同一语义映射。版本以当前项目锁文件及官方兼容资料为准。

## 4. 开发中的约束

- 颜色、间距、圆角、尺寸优先取 token；新增值先说明用途，加入共享或项目扩展语义，补齐浅深。
- 不将静态清册 demo 的字段、导航或占位品牌复制为其他产品业务结构。
- 不用所有按钮变大来弥补正文太小；不加重复导航；不让侧栏跟主内容滚动。
- 不通过统一 opacity 制造 disabled/placeholder；不为深色链接直接复用实心 primary。
- 不把 import tokens 当组件完成；真实组件状态、响应式、滚动轨道和可访问语义需实现。
- 将品牌变更提案与普通开发分开；未经授权只保留产品现有 VI，不能说“规范要求改名/换标”。

## 5. 提交前报告模板

```text
已改：文件/路由/组件
规范对应：采用的token、组件状态、模板及品牌配置
机器检查：命令、通过数、失败项（未运行则明确）
浏览器检查：主题、视口、缩放、滚动、键盘、表单底栏
截图：同路由同数据，浅深/宽窄，说明状态
偏离：条款、原因、批准依据
未完成：明确影响及下一步，不宣称已完成
```
