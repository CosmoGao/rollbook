# 发版文档检查

本规则适用于发布 PR、整体验收和 tag 前核验。文档修订本身不需要新 tag 或重发镜像。

1. 在发布 PR 中同步更新 `CHANGELOG.md`：按版本倒序添加对应 Release 链接，并将新增、变更、修复、安全或升级事项归入适用分类。逐项对照目标 tag 与上一正式 tag 的提交区间、已合并 PR 和 Release 正文；没有证据的版本或条目不得编造。
2. 只要用户可见行为、页面、命令、配置、部署或兼容性发生变化，就在同一 PR 中同步更新 `README.md` 和 `README.en.md`。两版须有相同章节、操作路径和安全边界；删除过期菜单与命令。检查示例在当前源码、`compose.yaml` 和 `.env.example` 中成立，且不含真实凭据。
3. 复核所有相对链接、Release 链接及截图。截图须来自目标版本，内容与界面一致且无密钥、账号等敏感信息。核对升级前备份、迁移、回退和密钥保持要求。
4. 测试审查在功能整体验收及发版核验中逐项检查上述文档，并记录结果；缺少 CHANGELOG、应更新却未更新任一语言 README、或链接/命令/升级回退说明错误时，不得发布。
5. 顺序：发布 PR 完成文档与本地校验 → CI 通过 → 测试审查通过 → 合并 → 再核对 Release 草稿与最终 tag 指向、文档和产物 → 推送 tag。不要在文档和验收尚未完成时先打 tag。

本仓库的文档修订 PR 只修改文档；若不包含用户行为或版本变化，无须补造新版本记录或重新发布镜像。
